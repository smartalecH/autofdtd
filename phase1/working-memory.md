## Decisions

- Reserve subsystem namespaces now: `api`, `core`, `geometry`, `materials`, `boundaries`, `sources`, `monitors`, `grid`, `modes`, `ir`, `compiler`, `runtime`, `kernels`, `diagnostics`, `examples`.
- Use `hatchling` with a `src/` layout and ship a small CLI (`autofdtd-feature-matrix`) so the scaffold has a concrete install/runtime smoke target before solver code exists.
- Keep this task focused on packaging, docs, and planning metadata; full tagged models remain for `task-002` and `task-003`.
- Model ordered overlap explicitly through `Scene.structures_in_resolution_order()`, sorting by resolved priority and then insertion order so later structures still win ties during sequential materialization.
- Keep the initial container layer serialization-light: `to_payload()`, `to_json_text()`, and `write_json()` are enough for snapshots and handoff, while `task-005` can generalize the shared model base.
- Use a generic family-tagged component envelope in the IR so Phase 1 can package realistic simulations before every feature family has concrete typed IR classes; later tasks can specialize payloads without changing bundle shape.
- Bundle packaging is directory-based: `manifest.json` points at a hashed `simulation.json` entrypoint, avoiding self-referential manifest hashing while staying suitable for remote upload or local caching.
- Core validation is checklist-driven: implemented feature tags pass, deferred or rejected tags fail early with explicit errors, and known primitive geometry payloads validate only when enough fields are present so placeholder tagged dicts can survive until their concrete family tasks land.
- Shared model behavior should live in `autofdtd.core.models`; public API and IR classes should subclass it rather than duplicating serialization or copy helpers in subsystem-local base classes.
- Primitive geometry stays axis-aligned in Phase 1 public models; scene-compilation transforms are still explicit so later `Transformed` and grouped-geometry tasks can lower onto the same contract instead of rewriting primitive handling.
- Structure precedence is now inspectable with `Scene.resolve_structure_at_point()`, which mirrors materialization order by applying primitive containment checks in resolved-priority order.
- Keep `GeometryArray` as a public wrapper only; repeated placements lower into ordinary grouped and transformed instances so runtime/compiler code can treat arrays as pre-expanded ordered geometry.
- Phase 1 `PolySlab` scope is intentionally limited to constant-cross-section extrusions of simple polygons on principal axes; non-zero `dilation` or `sidewall_angle`, self-intersections, and curved or boolean polygon features must fail explicitly until later geometry tasks land.
- Keep the feature ledger conservative for clipping: `ClipOperation` remains a deferred family in `planning.py`, but geometry validation explicitly allows the implemented subset and rejects unsupported boolean ops with clear errors.
- Phase 1 transform wrappers are rigid only; free-form affine matrices and exact boolean meshing remain out of scope even though the public model now supports grouped and transformed composition.
- Keep the top-level simulation grid surface strict: `grid_spec` must be a `GridSpec`, `AutoGrid` requires `GridSpec.wavelength`, and `QuasiUniformGrid` remains an explicit deferred error.
- Phase 1 AutoGrid is deliberately narrow: derive a vacuum baseline from wavelength and domain size, discretize piecewise with a simple `max_scale` grading pass, and limit refinement inputs to `LayerRefinementSpec` body and bound hints rather than full geometry-driven meshing.
- Keep Phase 1 subpixel support narrow and explicit: dielectric interfaces may use `PolarizedAveraging` or `Staircasing`, while metal, PEC, PMC, and lossy-metal interfaces stay staircasing-only until anisotropic media and conformal policies land.
- Treat PEC and PMC as explicit constitutive clamp modes in coefficient compilation and runtime helpers instead of pretending they are extremely lossy ordinary media.
- Phase 1 `PoleResidue` keeps complex numbers JSON-safe as `(real, imag)` tuples in the public API and IR so serialization stays stable without inventing ad hoc string encoding.
- Phase 1 PoleResidue runtime support is electric-only and uses one complex polarization accumulator per pole; magnetic dispersion remains out of scope until later material families require it.
- Phase 1 `Sellmeier` support is intentionally passive-only and homogeneous-only: `B_i >= 0`, `C_i >= 0`, zero-`C_i` terms fold into `eps_inf`, and all timestep execution reuses the existing electric-only `PoleResidueMaterialCoefficients` path instead of creating a new auxiliary-state layout.
- Phase 1 `Lorentz` is passive-only (`delta_eps >= 0`, `damping >= 0`, `frequency^2 != damping^2`), `Drude` is limited to damped poles (`damping > 0`) so it can lower cleanly onto the current pole-residue path, and `Debye` is passive-only (`delta_eps >= 0`, `tau > 0`).
- The current exact-hold pole-residue recurrence path can overflow for sufficiently stiff poles relative to `dt`; material compilation now raises an explicit error instead of emitting unusable coefficients, which is especially relevant for very small-`tau` Debye fits.
- Phase 1 anisotropy stops at diagonal tensor media: `AnisotropicMedium` is implemented and IR-lowered, `FullyAnisotropicMedium` remains an explicit deferred error for runtime compilation, and `Medium2D` remains a deferred direct-simulation feature with offline conversion helpers only.
- Advanced material policy is explicit rather than silent: `LossyMetalMedium` and perturbation media are parseable defer buckets with manual fallback helpers, while sampled `Custom*` media are parsed or bucketed only to produce clear reject errors.
- Phase 1 boundary runtime support now covers `Periodic`, `BlochBoundary`, `PECBoundary`, `PMCBoundary`, and baseline `PML`; `StablePML`, `Absorber`, and ABC-family entries remain outside the runtime compiler until later boundary tasks land.
- Conductor boundaries are represented as reflection-sign transforms rather than special-casing them inside the future timestep loop: PEC uses odd tangential electric and odd normal magnetic parity, while PMC uses the opposite parity assignment.
- Keep Phase 1 PML deliberately narrow: use Tidy3D-shaped `num_layers + parameters + extrude_structures` public models, compile one profile per boundary face, and treat the first runnable backend as a staged damping layer with persistent face memory rather than a full split-field CPML implementation.
- Keep `StablePML` as a preset-driven extension of the baseline staged PML backend in Phase 1 rather than a separate field-splitting formulation; runtime differentiation is through compiled profile metadata and defaults, not a distinct kernel family.
- Keep `Absorber` practical and explicit: Phase 1 uses a conductivity-ramp absorbing subset with no auxiliary memory contribution and a PEC-like outer-wall reflection policy, trading fidelity for a clear stable fallback when baseline PML is unsuitable.
- Keep `ABCBoundary` practical and narrow: Phase 1 implements only the explicit-parameter first-order subset, and automatic medium inference plus mode-based ABC stay deferred until scene-material sampling and mode-solver tasks are available.
- Keep runtime convergence explicit and narrow: Phase 1 shutoff is the Tidy3D-style ratio of instantaneous integrated electric-field intensity to its historical maximum, checked on a configurable step interval; material-aware CFL relaxation and richer convergence heuristics remain deferred.
- Keep runtime logging separate from benchmark metrics: Phase 1 emits deterministic progress records at step 0, configurable progress intervals, and final stop, while every shutoff check still lands in convergence evidence even when progress logging is downsampled.
- Keep Phase 1 source-time scope narrow and explicit: implement `GaussianPulse` and `ContinuousWave` as standalone immutable models first, preserve Tidy3D-style `freq0`/`fwidth`/`offset` semantics plus `remove_dc_component` on Gaussian pulses, and defer broader source-time families to their own tasks instead of hiding them behind loose dict payloads.
- Phase 1 `BroadbandPulse` is a clearly delimited analytic subset: represent it as a Gaussian-modulated carrier derived from `(freq_range, minimum_amplitude)` rather than trying to reproduce Tidy3D's licensed extension internals, and keep `CustomSourceTime` as explicit sample interpolation with nearest-value clamping outside the provided range.
- Phase 1 `UniformCurrentSource` uses primal-cell placement metadata rather than hidden source snapping: zero-size axes interpolate between neighboring cell centers when enabled, finite extents either select center-in-bounds cells or overlap-fraction weights when `confine_to_bounds=True`, and `"total"` amplitude normalization divides by the local transverse extent implied by the source geometry and resolved grid.

## Task Handoffs

- `task-003` should add versioned IR models under `autofdtd.ir` without coupling them to the public API module layout; it can treat `Simulation.to_payload()` as an interim handoff format, not the final IR contract.
- Later geometry, material, source, and monitor tasks can plug concrete tagged models into the existing container fields without changing the ordered-container semantics.
- `task-004` and `task-005` can reuse `ComponentIR.payload` plus the shared IR schema version constants instead of inventing another transport shape.
- Later geometry, source, monitor, boundary, and grid tasks should route new object models through `autofdtd.core.validation.normalize_component()` or extend its equivalents instead of scattering policy checks across each family.
- Later compiler work can rely on wrapper IR bounds as conservative planning envelopes; exact voxelization or boolean rasterization still belongs in scene compilation rather than the public geometry layer.
- Later compiler work can consume `StructureIR.source_index` plus `StructureIR.precedence_rank` directly when building ordered region materialization plans or conflict diagnostics.
- Later grid/compiler tasks should treat `LayerRefinementSpecIR` as planning metadata only; corner finding, snapping-point localization, and structure-derived meshing still need a separate scene-aware meshing pass.
- Material and compiler tasks should consume `SubpixelSpecIR.averaging_targets` and `requires_anisotropic_materialization` directly instead of re-deriving which interface families need tensor-valued effective media.
- Later runtime and chunk-planning tasks can treat `IsotropicMaterialCoefficients` plus `ConstitutiveMode` as the stable baseline constitutive contract before dispersive and anisotropic state is added.
- Later Lorentz, Drude, Debye, and Sellmeier tasks should lower onto the `PoleResidueMaterialCoefficients` auxiliary-state contract whenever the family can be reduced to pole-residue terms instead of creating parallel runtime state layouts.
- Later subpixel materialization work can target `AnisotropicMaterialCoefficients` plus the diagonal anisotropic kernel path instead of inventing a separate tensor-material runtime for effective-media smoothing.
- Later absorbing-boundary tasks should extend `CompiledBoundarySpec` and the boundary ghost-update stage rather than reworking the public `Boundary` or `BoundarySpec` container semantics; Bloch, symmetry, and baseline PML metadata now already live on that runtime contract.
- `task-022` should either preserve the `PMLParams` coefficient-shape contract for `StablePML` / `Absorber` or add a clearly separate compiled-face payload; `allocate_pml_boundary_state()` and `apply_boundary_stages()` are the current extension seams.
- Later ABC-boundary work should treat the current `pml_faces` metadata on `CompiledBoundarySpec` as the legacy absorbing-face alias and prefer the newer `stable_pml_faces` / `absorber_faces` tags when family-specific behavior matters.
- Later mode-ABC work should extend the new `abc_faces` / staged-ABC seam rather than folding mode-aware behavior into the generic halo transform path; the current deferral is specifically about mode-solver dependency, not about the ABC stage layout itself.
- Later execution-loop tasks should treat `CompiledRuntimeControls` and `RuntimeController` as the stable seam for stop reasons, early-stop evidence, and step-budget bookkeeping rather than burying convergence logic inside kernels or chunk schedulers.
- Later execution-loop tasks should route full Maxwell stepping through `RuntimeProgressLogger` / `RuntimeExecutionLog` instead of inventing a second progress format; benchmark tasks can layer throughput and JIT timing on top of the existing log bundle rather than mixing those concerns into debugging output.
- Later source-family tasks should reuse `source_time_model_from_value()` and `source_time_to_ir()` as the normalization and lowering seam for nested `source_time` fields instead of reimplementing waveform parsing inside each source model.
- Later source-time expansions should preserve the current JSON-safe complex-pair representation for custom envelopes so package serialization and IR transport stay stable even if dataset-backed APIs are added later.
- Later `PointDipole` and `CustomCurrentSource` work should reuse `CompiledAxisPlacement` / `CompiledUniformCurrentSource` conventions where possible, extending them for Yee-staggered component placement or dataset-driven amplitudes instead of inventing a separate source-placement runtime contract.
